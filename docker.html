MODULE 1: The Docker Mental Model

1.1 What is Docker?

WHAT Docker is a way to package your application + its runtime (JDK) + its config into a single, portable unit called an Image, which runs as a Container.
WHY Without it, you face the "It works on my machine" curse. Manual setup on servers is slow, error-prone, and inconsistent across environments (Dev vs Prod).
HOW By using a Dockerfile (blueprint) to build an Image (immutable template), which then spawns Containers (running instances).

1.2 Core Terminology

  • Image: The static "snapshot" of your app. Think of it as a Class in Java.
  • Container: The running instance of an Image. Think of it as an Object in Java.
  • Registry: A storage for images (like Docker Hub or GitHub Container Registry).

MODULE 2: The JAR Foundation

2.1 Jar Creation

WHAT A JAR is the compiled, packaged version of your Spring Boot code.
WHY Docker does not care about your Java classes or packages. It only understands files. The JAR is the executable artifact Docker needs to run.
HOW Run this in your project root: 
mvn clean package
Output: target/my-app-0.0.1-SNAPSHOT.jar
Crucial Rule If your app doesn't work locally (via java -jar), it will NEVER work in Docker. Fix the build first.

MODULE 3: Dockerfile Deep Dive

3.1 The Basic Dockerfile

FROM openjdk:17-jdk-slim
WORKDIR /app
COPY target/my-app.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

3.2 Instruction Breakdown

3.2.1 FROM

WHAT: Defines the base image.
WHY: You don't want to install Linux or Java manually every time. Base images provide the OS + Runtime.
HOW: FROM openjdk:17-jdk-slim. Always match your project's Java version.

3.2.2 WORKDIR

WHAT: Sets the working directory inside the container.
WHY: Avoids cluttering the root (/) and provides a predictable path for execution.
HOW: WORKDIR /app. All subsequent commands run here.

3.2.3 COPY

WHAT: Moves files from your laptop into the Docker Image.
WHY: Containers are isolated; they cannot see your local files unless you explicitly copy them.
HOW: COPY target/*.jar app.jar. (Left: Host, Right: Container).

3.2.4 EXPOSE

WHAT: Documentation of the used port.
WHY: Purely for communication clarity between developers and orchestration tools.
HOW: EXPOSE 8080. ⚠️ Important: This does NOT publish the port.

3.2.5 ENTRYPOINT

WHAT: The command that runs when the container starts.
WHY: A container without a running process dies immediately.
HOW: ENTRYPOINT ["java", "-jar", "app.jar"].

MODULE 4: Build & Run

4.1 Building the Image

WHAT Converting your Dockerfile into a usable Image.
HOW 
docker build -t my-spring-app .
  • -t: Tag (name) of the image.
  • .: The current directory (Build Context).

4.2 Running the Container

WHAT Starting a live instance of your image.
HOW 
docker run -p 8080:8080 my-spring-app
Port Mapping: HOST : CONTAINER.

MODULE 5: Env Variables & Port Mapping

5.1 Environment Variables

WHAT Injecting configuration at runtime without changing the code.
WHY Security (no passwords in code) and Flexibility (same image, different DBs).
HOW In application.yml: 
spring:
  datasource:
    url: ${DB_URL}
When running Docker: 
docker run -e DB_URL=jdbc:postgresql://host:5432/db -p 8080:8080 my-app

MODULE 6: Industrial Multi-stage Build

WHAT A Dockerfile with two parts: one to Build (needs Maven) and one to Run (needs only JRE).
WHY Standard builds include Maven and source code in the final image, making it huge (~600MB) and insecure. Multi-stage results in a sleek (~150MB) production-ready image.
HOW 
# STAGE 1: Build
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY . .
RUN mvn clean package -DskipTests

# STAGE 2: Run
FROM eclipse-temurin:17-jre-jammy
WORKDIR /app
COPY --from=builder /build/target/*.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]

MODULE 7: Docker Compose (Spring + DB)

7.1 What is Docker Compose?

WHAT: A tool for defining and running multi-container applications.
WHY: Real apps need a DB. Running 5 docker run commands manually is a nightmare.
HOW: Use a docker-compose.yml file.

7.2 The Compose File

version: "3.9"
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: mydb
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data

  app:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - db
    environment:
      DB_URL: jdbc:postgresql://db:5432/mydb

volumes:
  pgdata:
Pro Tip: Inside the Docker network, use the service name (e.g., db) as the hostname. Not localhost!

MODULE 8: Microservices Orchestration

8.1 Service Discovery

WHAT Services finding each other by name within a network.
WHY In microservices, IP addresses change constantly. Names stay the same.
HOW Docker creates an internal DNS. If service A wants to call service B, it just hits http://service-b:8080.

8.2 Typical Layout

/project-root
 ├── gateway-service/ (Dockerfile)
 ├── user-service/    (Dockerfile)
 ├── order-service/   (Dockerfile)
 └── docker-compose.yml

MODULE 9: AWS EC2 Deployment

9.1 The Flow

WHAT Running your Docker containers on a cloud virtual server.
WHY To make your app accessible to the world.

9.2 How to Deploy (Step-by-Step)

Click to view deployment steps
  1. Spin up EC2: Amazon Linux 2023 (T2.Micro is free).
  2. Open Ports: Security Group -> Inbound Rules -> Add 8080.
  3. Install Docker on EC2: 
    sudo yum update -y
sudo yum install docker -y
sudo systemctl start docker
sudo usermod -aG docker ec2-user
  4. Pull & Run: 
    docker pull your-name/my-app
docker run -d -p 8080:8080 your-name/my-app

MODULE 10: Pro Debugging

10.1 The Debugging Toolkit

WHAT The skill of finding out why a container is "dead" or behaving weirdly.
Command Usage
docker ps -a See even crashed containers.
docker logs [id] Read the Spring Boot log output.
docker exec -it [id] sh "Enter" the container to check files.
docker system prune Cleanup: Delete all unused data.

MODULE 11: Interview Mastery Q&A

Q: Why use Docker for Spring Boot instead of just JARs?
Answer: JARs only solve code portability. Docker solves "Environment Portability". JARs require you to install specific JDK versions and OS configs manually; Docker packages EVERYTHING.
Q: Difference between CMD and ENTRYPOINT?
Answer: ENTRYPOINT is the main command that is not supposed to be overridden. CMD provides default arguments that can be easily overridden when starting the container.
Q: Container is running but http://localhost:8080 fails. Why?
Answer: Most common reason: Forgot -p 8080:8080. Without port mapping, the container's port is isolated from your host's network.
Q: How do you persist data in a database container?
Answer: Using Volumes. Volumes map a directory inside the container to a directory on your laptop, so data survives even if the container is deleted.
