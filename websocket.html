1. First Understand The Big Picture

Think of the entire system like this:

  • HTTP = Normal request/response
  • WebSocket = Permanent TCP communication pipe
  • STOMP = Messaging protocol inside that pipe
  • Spring Broker = Traffic manager/router

2. High Level Architecture

flowchart LR A[Frontend Browser] --> B[WebSocket Connection] B --> C[STOMP Frames] C --> D[Spring WebSocket Endpoint] D --> E[Spring Messaging Infrastructure] E --> F[MessageMapping Controllers] F --> G[Business Logic] G --> H[Message Broker] H --> I[Subscribed Clients]

3. Why WebSocket Exists

Traditional HTTP

Client ---> Request ---> Server
Client <--- Response <--- Server

Connection closes after response.

Problem

Realtime systems need server-to-client push communication:

  • chat apps
  • stock market
  • multiplayer games
  • notifications
  • live dashboards

Solution

WebSocket keeps ONE TCP connection permanently open.

4. Detailed Connection Lifecycle

Step 1 — HTTP Handshake

Browser first sends a normal HTTP request to: 

/ws

This is NOT yet a WebSocket connection.

Browser is asking: 

Can we upgrade this HTTP connection into WebSocket?

Step 2 — HTTP Upgrade

Browser sends special headers: 

Upgrade: websocket
Connection: Upgrade

Spring responds: 

HTTP 101 Switching Protocols

Now normal HTTP ends.

The SAME TCP socket becomes a persistent WebSocket connection.

Very Important Understanding

WebSocket physical connection exists ONLY at: 

/ws

NOT at: 

/app
/topic

Those are STOMP destinations INSIDE the WebSocket connection.

5. What Is STOMP?

WebSocket only provides a communication pipe.

It DOES NOT define:

  • subscriptions
  • topics
  • routing
  • broadcasting
  • message semantics

STOMP solves this problem.

STOMP is a messaging protocol running INSIDE WebSocket.

@Configuration

public class WebSocketConfig
      implements WebSocketMessageBrokerConfigurer {

    public void registerStompEndpoints(
        StompEndpointRegistry registry) {

        registry
            .addEndpoint("/ws")
            .setAllowedOriginPatterns("*")
            .withSockJS();
    }

    @Override
    public void configureMessageBroker(
        MessageBrokerRegistry registry) {

        registry.setApplicationDestinationPrefixes("/app");

        registry.enableSimpleBroker(
            "/topic",
            "/queue"
        );
    }
}

12. What Each Configuration Really Means

EnableWebSocketMessageBroker

Activates Spring STOMP messaging infrastructure.

Without this:

  • no broker
  • no STOMP routing
  • no subscriptions
  • no message channels

addEndpoint ws

Creates HTTP handshake endpoint.

Browser initially connects here using HTTP.

After successful upgrade: 

HTTP -> WebSocket TCP Connection

Important:

This endpoint is the PHYSICAL socket connection endpoint.

withSockJS

Fallback mechanism when browser/network cannot use native WebSocket.

SockJS may fallback to:

  • long polling
  • xhr streaming
  • event source

setApplicationDestinationPrefixes app

Defines incoming routing prefix.

Anything sent to: 

/app/**

gets routed into Spring controllers.

Example: 

SEND /app/chat

Spring removes: 

/app

Then maps remaining destination: 

/chat

to: 

@MessageMapping("/chat")

enableSimpleBroker topic queue

Creates internal in-memory message broker.

Broker handles:

  • subscriptions
  • broadcasting
  • session tracking
  • message fanout

28. Dynamic Messaging with SimpMessagingTemplate

Sometimes you need to send a message NOT as a response to a client's message, but from a background job, an external API call, or a scheduled task. 

@Service
public class NotificationService {

    private final SimpMessagingTemplate messagingTemplate;

    public NotificationService(SimpMessagingTemplate messagingTemplate) {
        this.messagingTemplate = messagingTemplate;
    }

    public void sendGlobalAlert(String message) {
        // Send to a topic (Broadcast to all)
        messagingTemplate.convertAndSend("/topic/alerts", message);
    }

    public void sendPrivateNotification(String username, String message) {
        // Send to a specific user
        messagingTemplate.convertAndSendToUser(
            username, 
            "/queue/notifications", 
            message
        );
    }
}

29. Tracking Online Users (WebSocket Events)

Spring broadcasts Application Events for WebSocket lifecycles. You can listen to these to track who is online. 

@Component
public class WebSocketEventListener {

    @EventListener
    public void handleWebSocketConnectListener(SessionConnectedEvent event) {
        System.out.println("Received a new web socket connection");
    }

    @EventListener
    public void handleWebSocketDisconnectListener(SessionDisconnectEvent event) {
        StompHeaderAccessor headerAccessor = StompHeaderAccessor.wrap(event.getMessage());
        String username = (String) headerAccessor.getSessionAttributes().get("username");
        
        if(username != null) {
            System.out.println("User Disconnected : " + username);
            // Broadcast user leave event
        }
    }
}

30. Securing WebSockets (Authentication & Interceptors)

Since WebSockets begin as an HTTP upgrade, you can authenticate during the HTTP handshake using standard session cookies. However, if you use stateless JWT tokens, it's common to pass the token in the STOMP CONNECT frame.

You intercept STOMP frames using a ChannelInterceptor before they reach the controllers: 

@Configuration
public class WebSocketSecurityConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureClientInboundChannel(ChannelRegistration registration) {
        registration.interceptors(new ChannelInterceptor() {
            @Override
            public Message<?> preSend(Message<?> message, MessageChannel channel) {
                StompHeaderAccessor accessor = 
                    MessageHeaderAccessor.getAccessor(message, StompHeaderAccessor.class);
                
                if (StompCommand.CONNECT.equals(accessor.getCommand())) {
                    String token = accessor.getFirstNativeHeader("Authorization");
                    // Validate JWT token here
                    // If valid, set the Principal for the session
                }
                return message;
            }
        });
    }
}

32. Core Spring Boot WebSocket Classes & Interfaces Reference

Spring Boot WebSocket infrastructure abstracts raw TCP socket communication into structured message-driven flows using a robust set of classes and interfaces. Below is the comprehensive guide to the core components, their structural roles, and concrete code implementations.

Quick Summary Reference

Class / Interface Type Primary Responsibility
WebSocketMessageBrokerConfigurer Interface The main configuration interface to enable and customize the STOMP message broker.
StompEndpointRegistry Interface Registers the HTTP URLs where clients handshake to initiate a WebSocket connection.
MessageBrokerRegistry Class Configures destination routing prefixes and chooses/tunes the message broker.
SimpMessagingTemplate Class Allows backend code (Services, Jobs) to publish messages programmatically to clients.

1. WebSocketMessageBrokerConfigurer (Interface)

This interface is implemented by configuration classes annotated with @EnableWebSocketMessageBroker. It provides callbacks to customize Spring Boot's WebSocket message handling.

Under the Hood:

When Spring starts up, it scans for classes implementing this configurer and calls their configuration hooks to populate the message channels, endpoints mapping, and message broker. 

@Configuration
@EnableWebSocketMessageBroker
public class CustomWebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // Defines the physical endpoint for WebSocket handshake connection
        registry.addEndpoint("/ws-connect")
                .setAllowedOriginPatterns("*")
                .withSockJS();
    }

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // Sets client-to-server destination prefix
        registry.setApplicationDestinationPrefixes("/app");
        // Sets up in-memory broker with prefixes for client subscriptions
        registry.enableSimpleBroker("/topic", "/queue");
    }

    @Override
    public void configureClientInboundChannel(ChannelRegistration registration) {
        // Registers custom channel interceptors
        registration.interceptors(new SecurityChannelInterceptor());
    }

    @Override
    public void configureWebSocketTransport(WebSocketTransportRegistration registration) {
        // Low-level buffer size, message size limits and send timeouts tuning
        registration.setMessageSizeLimit(128 * 1024)       // Max size: 128KB
                    .setSendTimeLimit(15 * 1000)            // Send timeout: 15s
                    .setSendBufferSizeLimit(512 * 1024);    // Buffer limit: 512KB
    }
}

2. StompEndpointRegistry (Interface)

Configures HTTP handshake endpoints mapping to underlying WebSocket handlers. Under the hood, this translates paths into a SimpleUrlHandlerMapping to route requests to WebSocketHttpRequestHandler.

Common Configuration Options:

  • addEndpoint(String... paths): Defines the handshake URI path.
  • setAllowedOriginPatterns(String... patterns): Configures allowed origins for CORS.
  • withSockJS(): Enables SockJS fallback protocol.
  • addInterceptors(HandshakeInterceptor... interceptors): Chain HTTP handshakes.
  • setHandshakeHandler(HandshakeHandler handshakeHandler): Customizes raw upgrade mechanism.
@Override
public void registerStompEndpoints(StompEndpointRegistry registry) {
    registry.addEndpoint("/chat-socket")
            .setAllowedOrigins("http://localhost:3000", "https://mychat.com")
            .addInterceptors(new CustomHandshakeInterceptor())
            .setHandshakeHandler(new CustomHandshakeHandler())
            .withSockJS();
}

3. MessageBrokerRegistry (Class)

Maintains destination prefixes and handles the activation of simple (in-memory) or external message brokers (RabbitMQ/ActiveMQ).

Simple Broker vs Broker Relay:

enableSimpleBroker() spins up an in-memory broker within Spring's JVM. enableStompBrokerRelay() starts a TCP relay client that connects to an external broker service (which must speak STOMP protocol, such as RabbitMQ's STOMP plugin). 

@Override
public void configureMessageBroker(MessageBrokerRegistry registry) {
    // Client-to-server destination prefix (intercepted by @MessageMapping)
    registry.setApplicationDestinationPrefixes("/app");
    
    // Configures Spring's TCP Broker Relay to connect to external RabbitMQ
    registry.enableStompBrokerRelay("/topic", "/queue")
            .setRelayHost("rabbitmq.local")
            .setRelayPort(61613) // Default STOMP Port
            .setClientLogin("user")
            .setClientPasscode("password")
            .setSystemLogin("admin")
            .setSystemPasscode("admin-pass");

    // Sets prefix for user-specific messaging (e.g. /user/queue/private)
    registry.setUserDestinationPrefix("/user");
}

4. SimpMessagingTemplate (Class)

Implements SimpMessageSendingOperations. This class allows programmatically sending messages to subscribers from anywhere in the application (like database triggers, background threads, REST controllers, or @Scheduled tasks).

Internal Routing Flow:

When you call convertAndSendToUser(username, destination, payload), the template resolves the username to their active STOMP session, rewrites the destination to /user/{username}-user{sessionId}/{destination} under the hood, and places it directly on the outbound message channel. 

@RestController
@RequestMapping("/api/chat")
public class RestChatController {

    private final SimpMessagingTemplate messagingTemplate;

    public RestChatController(SimpMessagingTemplate messagingTemplate) {
        this.messagingTemplate = messagingTemplate;
    }

    // HTTP Endpoint triggers a message to WebSocket clients
    @PostMapping("/broadcast")
    public ResponseEntity<Void> sendBroadcast(@RequestBody String message) {
        // Send directly to the WebSocket topic /topic/announcements
        messagingTemplate.convertAndSend("/topic/announcements", message);
        return ResponseEntity.ok().build();
    }

    // Sends private notification to user
    @PostMapping("/notify/{username}")
    public ResponseEntity<Void> sendNotification(@PathVariable String username, @RequestBody String alert) {
        // Resolves user's session and sends to /user/<username>/queue/alerts
        messagingTemplate.convertAndSendToUser(username, "/queue/alerts", alert);
        return ResponseEntity.ok().build();
    }
}

5. ChannelInterceptor (Interface)

Acts as a intercepting filter for messages passing through the client inbound/outbound channels or broker channels. This is the optimal place to implement token authentication (JWT), logging, or auditing.

Common Interceptor Methods:

  • preSend(Message<?> msg, MessageChannel ch): Invoked before sending the message. Return null to block the message.
  • postSend(Message<?> msg, MessageChannel ch, boolean sent): Invoked after a successful channel write.
  • afterSendCompletion(Message<?> msg, MessageChannel ch, boolean sent, Exception ex): Invoked after sending completes.
public class JwtAuthenticationInterceptor implements ChannelInterceptor {

    @Override
    public Message<?> preSend(Message<?> message, MessageChannel channel) {
        StompHeaderAccessor accessor = MessageHeaderAccessor.getAccessor(message, StompHeaderAccessor.class);

        // Intercept CONNECT commands to authenticate users
        if (accessor != null && StompCommand.CONNECT.equals(accessor.getCommand())) {
            String token = accessor.getFirstNativeHeader("Authorization");
            if (token != null && token.startsWith("Bearer ")) {
                String jwt = token.substring(7);
                if (validateToken(jwt)) {
                    Principal principal = extractPrincipal(jwt);
                    accessor.setUser(principal); // Associate security identity
                } else {
                    throw new MessageDeliveryException("Invalid JWT authentication token.");
                }
            }
        }
        return message; // Pass the message down the pipeline
    }

    private boolean validateToken(String token) { /* Token check logic */ return true; }
    private Principal extractPrincipal(String token) { return () -> "authenticated_user"; }
}

6. StompHeaderAccessor & MessageHeaderAccessor (Classes)

Spring's raw Message<?> represents headers as an immutable map. StompHeaderAccessor provides wrapper methods to easily read, write, and manipulate STOMP-specific headers, frame types, commands, and session details.

Session Attributes:

Through getSessionAttributes(), you can store data associated with the client socket session, which will persist across successive messages sent by the client. 

// Wrapping a raw spring-messaging Message
public void processMessage(Message<?> rawMessage) {
    StompHeaderAccessor accessor = StompHeaderAccessor.wrap(rawMessage);
    
    // Access native STOMP headers
    String origin = accessor.getFirstNativeHeader("Origin");
    
    // Access STOMP commands
    StompCommand command = accessor.getCommand();
    
    // Read custom session attributes
    Map<String, Object> attrs = accessor.getSessionAttributes();
    String currentRoom = (String) attrs.get("room_id");
}

7. HandshakeInterceptor (Interface)

Runs during the HTTP Handshake phase. It allows copying standard HTTP attributes (such as cookies, query parameters, or HttpSession attributes) into the WebSocket session attributes map, making them available to STOMP message interceptors and controllers.

Key Methods:

  • beforeHandshake(...): Invoked before upgrading. Return false to cancel connection.
  • afterHandshake(...): Invoked after upgrade succeeds.
public class CopySessionHandshakeInterceptor implements HandshakeInterceptor {

    @Override
    public boolean beforeHandshake(ServerHttpRequest request, ServerHttpResponse response, 
                                   WebSocketHandler wsHandler, Map<String, Object> attributes) throws Exception {
        if (request instanceof ServletServerHttpRequest) {
            ServletServerHttpRequest servletRequest = (ServletServerHttpRequest) request;
            HttpServletRequest httpServletRequest = servletRequest.getServletRequest();
            
            // Extract attributes from HttpSession
            String userId = (String) httpServletRequest.getSession().getAttribute("userId");
            if (userId != null) {
                // Copy into WebSocket session attributes map
                attributes.put("userId", userId);
            }
        }
        return true; // Return true to continue upgrade
    }

    @Override
    public void afterHandshake(ServerHttpRequest request, ServerHttpResponse response, 
                               WebSocketHandler wsHandler, Exception exception) {}
}

8. HandshakeHandler & DefaultHandshakeHandler (Interface / Class)

Responsible for handling the actual WebSocket protocol negotiation and connection upgrade from HTTP to TCP. You typically extend DefaultHandshakeHandler to assign a security Principal to the connection based on attributes gathered during the handshake. 

public class CustomHandshakeHandler extends DefaultHandshakeHandler {

    @Override
    protected Principal determineUser(ServerHttpRequest request, WebSocketHandler wsHandler, 
                                      Map<String, Object> attributes) {
        // Extract the user identity copied from HandshakeInterceptor attributes
        String userId = (String) attributes.get("userId");
        if (userId != null) {
            // Assign this principal to the WebSocket connection.
            // Spring will map private /user messages to this Principal.
            return () -> userId;
        }
        return null; // Anonymous user
    }
}

9. WebSocket Application Events (Classes)

Spring publishes lifecycle events via ApplicationEventPublisher that you can listen to using @EventListener to track user logins, logouts, topic subscriptions, or connections.

Available Lifecycle Events:

  • SessionConnectEvent: Triggered when a raw STOMP CONNECT frame is received.
  • SessionConnectedEvent: Triggered when the server returns a STOMP CONNECTED acknowledgement frame.
  • SessionSubscribeEvent: Triggered when a client subscribes to a topic.
  • SessionUnsubscribeEvent: Triggered when a client unsubscribes.
  • SessionDisconnectEvent: Triggered when the physical TCP socket or STOMP session terminates.
@Component
public class PresenceEventListener {

    // Track active user count or state
    private final ConcurrentHashMap<String, String> activeSessions = new ConcurrentHashMap<>();

    @EventListener
    public void handleConnect(SessionConnectedEvent event) {
        StompHeaderAccessor accessor = StompHeaderAccessor.wrap(event.getMessage());
        String sessionId = accessor.getSessionId();
        Principal user = accessor.getUser();
        
        if (user != null) {
            activeSessions.put(sessionId, user.getName());
            System.out.println("User " + user.getName() + " joined chat session: " + sessionId);
        }
    }

    @EventListener
    public void handleDisconnect(SessionDisconnectEvent event) {
        StompHeaderAccessor accessor = StompHeaderAccessor.wrap(event.getMessage());
        String sessionId = accessor.getSessionId();
        String username = activeSessions.remove(sessionId);
        
        if (username != null) {
            System.out.println("User " + username + " left session: " + sessionId);
        }
    }
}

10. Annotation Routing Mapping (@MessageMapping, @SendTo, @SendToUser)

Placed on controller methods to control incoming routing and response distribution. 

@Controller
public class WebSocketChatController {

}

33. Horizontal Scaling & Load Balancing

In a multi-instance (clustered) production environment, scaling WebSockets presents unique challenges because WebSocket connections are stateful and persistent.

The Stateful Challenge

Unlike REST endpoints (which are stateless), a client keeps a single TCP connection open with a specific server instance. If Client A is connected to Instance 1, and Client B is connected to Instance 2:

  • Instance 1 cannot send messages directly to Client B.
  • If Instance 1 broadcasts a message to /topic/chat, only clients connected to Instance 1 will receive it.

1. Solving the Broadcast Problem with Shared Brokers

To scale horizontally, you must replace Spring’s in-memory Simple Broker with a shared external message broker (such as RabbitMQ or ActiveMQ) via enableStompBrokerRelay().

How it works: When Client A publishes a message to Node 1, Node 1 forwards it to RabbitMQ. RabbitMQ distributes (fans out) the message to all server nodes (Node 1 and Node 2) subscribed to that topic. Node 2 then pushes the message down the socket to Client B.

2. Load Balancer Configuration & Sticky Sessions

When configuring load balancers (like Nginx, HAProxy, AWS ALB) in front of a Spring Boot WebSocket cluster:

Key Requirements:

  • WebSocket Upgrades: The load balancer must be configured to pass the Upgrade and Connection HTTP headers. Without this, the handshake will fail.
  • Sticky Sessions (Session Affinity): Absolutely critical if you use **SockJS fallbacks** (like HTTP Long Polling). Long polling consists of consecutive, separate HTTP requests representing the same logical connection. If Request 1 hits Node 1 and Request 2 hits Node 2, the SockJS session will be lost and errors will be thrown.
  • Connection Timeouts: WebSockets can close due to inactivity. Ensure the load balancer's idle timeout is set high enough, and keep-alive heartbeats are configured on the client/broker.

Example Nginx Proxy Configuration:

http {
    upstream websocket_cluster {
        # enable sticky sessions using ip_hash or cookies
        ip_hash;
        server backend1.example.com:8080;
        server backend2.example.com:8080;
    }

    server {
        listen 80;

        location /ws-connect/ {
            proxy_pass http://websocket_cluster;
            proxy_http_version 1.1;
            
            # Critical headers for upgrading HTTP to WebSocket
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
            
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            
            # Increase timeouts to prevent early disconnection
            proxy_read_timeout 86400s;
            proxy_send_timeout 86400s;
        }
    }
}

34. Integration Testing WebSockets

Testing WebSockets in Spring Boot requires simulating a running server and connecting as a client asynchronously. Spring Boot's integration testing suite allows connecting to a running server using WebSocketStompClient.

Testing Strategy

Since WebSocket messaging is asynchronous, test methods must wait for messages using synchronization classes (like CompletableFuture or CountDownLatch). If the message is not received within a timeout window, the test fails.

Example WebSocket Integration Test:

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
public class WebSocketChatIntegrationTest {

    @LocalServerPort
    private int port;

    private WebSocketStompClient stompClient;

    @BeforeEach
    public void setup() {
        // Configure standard client transport with SockJS support
        this.stompClient = new WebSocketStompClient(
            new SockJsClient(List.of(new WebSocketTransport(new StandardWebSocketClient())))
        );
        
        // Configure message converters (Jackson JSON serializer)
        stompClient.setMessageConverter(new MappingJackson2MessageConverter());
    }

    @Test
    public void testPublishAndSubscribeFlow() throws Exception {
        CompletableFuture<ChatMessage> completableFuture = new CompletableFuture<>();
        String wsUrl = "ws://localhost:" + port + "/ws-connect";

        // 1. Handshake and connect to the endpoint
        StompSession session = stompClient
            .connectAsync(wsUrl, new StompSessionHandlerAdapter() {})
            .get(3, TimeUnit.SECONDS); // Timeout after 3 seconds

        // 2. Subscribe to the public topic
        session.subscribe("/topic/global-chat", new StompFrameHandler() {
            @Override
            public Type getPayloadType(StompHeaders headers) {
                return ChatMessage.class;
            }

            @Override
            public void handleFrame(StompHeaders headers, Object payload) {
                // Complete the future when the message arrives
                completableFuture.complete((ChatMessage) payload);
            }
        });

        // 3. Publish a message to the controller destination
        ChatMessage sentMessage = new ChatMessage("Alice", "Hello Spring WebSockets!");
        session.send("/app/chat.send", sentMessage);

        // 4. Assert that the message is received asynchronously on the topic subscription
        ChatMessage receivedMessage = completableFuture.get(5, TimeUnit.SECONDS);
        
        assertNotNull(receivedMessage);
        assertEquals("Alice", receivedMessage.getSender());
        assertEquals("Hello Spring WebSockets!", receivedMessage.getContent());
    }
}
