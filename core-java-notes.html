3.1 Core Concepts Deep Dive: Cohesion & Binding

This section explores the fundamental mechanics that enable Polymorphism and robust design.

1️⃣ Cohesion (Design Foundation)

What is Cohesion?
Cohesion measures how strongly related the responsibilities of a class or method are.

  • High cohesion = one class does one job well.
  • Low cohesion = one class does many unrelated things.

❌ Low Cohesion (Bad)

class UserService {
    void login() {}
    void generatePDF() {}
    void sendEmail() {}
    void connectToDatabase() {}
}
Problems Hard to maintain, changes ripple everywhere, and difficult testing.

✅ High Cohesion (Good)

class AuthService {
    void login() {}
    void logout() {}
}

class EmailService {
    void sendEmail() {}
}
Benefits Easier maintenance, clear responsibility, reusable & testable.

2️⃣ Binding (Core Execution Concept)

Binding = connecting a method call to the method implementation.

obj.method();  // which method body?

1. Static Binding (Compile-Time / Early Binding)

  • Bound before execution, during compilation.
  • Happens with: static, final, private methods, and Method Overloading.
class A {
    static void show() { System.out.println("A"); }
}
A.show(); // Compiler knows exactly what to call

2. Dynamic Binding (Runtime / Late Binding)

  • Bound during execution.
  • Happens with: Method Overriding and Parent reference → Child object.
class A {
    void show() { System.out.println("A"); }
}
class B extends A {
    void show() { System.out.println("B"); }
}

A obj = new B();
obj.show();  // B.show() -> JVM decides at runtime
Key Rule Methods are bound using the object type, not the reference type (except static/private/final).

3️⃣ Binding Consequence #1: Polymorphism

One interface, many implementations. Example: A obj = new B();

Compile-time vs Runtime Polymorphism

Type Mechanism Binding
Compile-time Overloading Static
Runtime Overriding Dynamic

JVM Insight (Intermediate+)

  • JVM uses a Virtual Method Table (V-Table).
  • Object holds method references.
  • Overridden method replaces parent entry.

4️⃣ Binding Consequence #2: Method Resolution

How Java resolves a method call:

  1. Compiler checks method existence using reference type.
  2. JVM checks overridden version using object type.
  3. Final method body executes.

5️⃣ Binding Consequence #3: Variable Resolution

Critical Variables are NOT polymorphic. 
class A { int x = 10; }
class B extends A { int x = 20; }

A obj = new B();
System.out.println(obj.x); // Output: 10

Why? Variables use reference type. No overriding. Compile-time resolution only.

6️⃣ Type Casting

Exists because Reference type and Object type are different.

1. Upcasting (Safe, implicit)

A obj = new B(); // Child → Parent

2. Downcasting (Unsafe, explicit)

B obj = (B) new A(); // ❌ Runtime Error (ClassCastException)

// Safe Downcasting
if (obj instanceof B) {
    B b = (B) obj;
}
Note Casting does NOT change the object. It only tells the compiler to treat the reference as a specific type.

7️⃣ Master-Level Mental Model

  • Reference Type → compiler rules
  • Object Type → runtime behavior
  • Method Type → binding decision
Interview One-liners
  • “Java achieves runtime polymorphism through dynamic binding.”
  • “Static methods are resolved using reference type.”
  • “Variables do not participate in polymorphism.”

The Collections Framework provides a set of classes and interfaces for storing and manipulating groups of objects.

10.1 Introduction: Arrays vs Collections

While arrays are useful for representing multiple values with a single variable, they have significant limitations.

Feature Arrays Collections
Size Fixed (cannot grow/shrink at runtime) Growable (Dynamic sizing)
Data Type Only Homogeneous Homogeneous & Heterogeneous
Memory Not memory efficient (wasted space if size is too large) Memory efficient
Ready-made methods Not available (must write logic manually) Extensive utility methods available
Performance High (better for primitive data) Slightly lower (due to object overhead)
Note Collections can only hold objects, not primitives. However, with Autoboxing (introduced in Java 1.5), we can directly add primitives, which are converted to Wrapper objects.

10.2 Key Interfaces Hierarchy

The Collection Framework is based on several key interfaces:

  • Collection: The root interface for all collections except Map.
  • List: Ordered collection with duplicates allowed (e.g., ArrayList, LinkedList).
  • Set: Unordered collection where duplicates are NOT allowed (e.g., HashSet, LinkedHashSet).
  • SortedSet/NavigableSet: Sets that maintain a sorting order (e.g., TreeSet).
  • Queue: For representing objects prior to processing (FIFO).
  • Map: Group of key-value pairs (NOT a child of Collection interface).

10.2.1 Collection Interface Methods

These methods are available in almost all collection classes:

  • add(Object o), addAll(Collection c)
  • remove(Object o), removeAll(Collection c), retainAll(Collection c)
  • contains(Object o), containsAll(Collection c)
  • isEmpty(), size(), clear()
  • iterator(), toArray()

10.3 List Interface Deep Dive

Used when insertion order must be preserved and duplicates are allowed.

1️⃣ ArrayList

  • Underlying Data Structure: Resizable/Growable Array.
  • Frequent Operation: Best for Retrieval (implements RandomAccess).
  • Worst Operation: Insertion/Deletion in middle (requires shift operations).
  • Initial Capacity: Default is 10.
  • New Capacity Formula: (CurrentCapacity * 3/2) + 1.
ArrayList al = new ArrayList();
al.add("A");
al.add(10);
al.add("A"); // Duplicates allowed
al.add(null); // Null allowed
System.out.println(al); // [A, 10, A, null]

2️⃣ LinkedList

  • Underlying Data Structure: Double Linked List.
  • Frequent Operation: Best for Insertion/Deletion in the middle.
  • Worst Operation: Retrieval (must traverse from start/end).
  • Implements Serializable and Cloneable but NOT RandomAccess.

3️⃣ Vector & Stack

  • Vector: Legacy class (1.0v), Thread-safe (methods are synchronized), slow performance.
  • Stack: Child class of Vector, designed for LIFO (Last-In-First-Out).
    • push(Object o): Add element.
    • pop(): Remove and return top element.
    • peek(): Return top element without removing.
    • empty(): Check if stack is empty.
    • search(Object o): Return 1-based offset from top.
Legacy Classes Vector and Stack are generally avoided in modern Java. Use ArrayList or Deque instead.
How to get a Synchronized ArrayList?

By default, ArrayList is non-synchronized. Use the Collections utility class:

List synchronizedList = Collections.synchronizedList(new ArrayList());

10.4 Cursors in Java

Used to retrieve objects one by one from a collection.

Cursor Applicable For Movement Access Type
Enumeration Legacy classes (Vector, Stack) Forward only Read only
Iterator Any Collection class (Universal) Forward only Read & Remove

10.5 Set Interface Deep Dive

Used when duplicates are NOT allowed and insertion order is not important.

1️⃣ HashSet

  • Underlying Data Structure: Hashtable.
  • Objects are inserted based on HashCode.
  • Best for Search operations.

2️⃣ LinkedHashSet

  • Hybrid Data Structure: Hashtable + Linked List.
  • Preserves Insertion Order.
  • Introduced in 1.4v. Best for cache-based applications.

3️⃣ TreeSet

  • Underlying Data Structure: Balanced Tree.
  • All elements are inserted according to Sorting Order.
  • Heterogeneous objects NOT allowed (will throw ClassCastException).

10.6 Sorting: Comparable vs Comparator

How Java decides the order of elements in Sorted collections.

Key Difference
  • Comparable: Meant for Default Natural Sorting (e.g., Ascending for numbers).
  • Comparator: Meant for Customized Sorting (e.g., Descending, sorting by Name/ID).
Feature Comparable Comparator
Package java.lang java.util
Method compareTo(Object obj) compare(obj1, obj2), equals()
Usage Single sorting logic Multiple customized sorting logics
Implemented By The actual Bean class (e.g., Student) A separate utility class 
// Example: compareTo return values
obj1.compareTo(obj2); 
// returns -ve if obj1 < obj2
// returns +ve if obj1 > obj2
// returns 0 if obj1 == obj2

10.7 Map Interface

Map is used when we want to represent data in Key-Value pairs. Each key must be unique, but values can be duplicated.

1️⃣ HashMap

  • Underlying Data Structure: Hashtable.
  • Insertion order NOT preserved (based on HashCode of keys).
  • Allows one null key and multiple null values.
  • Non-synchronized (not thread-safe).
  • Initial Capacity: 16
  • Load Factor: 0.75

2️⃣ LinkedHashMap

  • Underlying Data Structure: Hashtable + Linked List.
  • Preserves Insertion Order.

3️⃣ TreeMap

  • Underlying Data Structure: Red-Black Tree.
  • Keys are sorted according to Default Natural Sorting Order or Customized Order.
  • Keys must be Homogeneous and Comparable.

4️⃣ Hashtable

  • Legacy class, Synchronized.
  • Null keys and Null values are NOT allowed (will throw NullPointerException).
  • Initial Capacity: 11
  • Load Factor: 0.75
Specialized Map Implementations
  • IdentityHashMap: Uses == operator for key comparison instead of equals().
  • WeakHashMap: Keys are wrapped in WeakReferences. Garbage Collector can remove entries if keys are no longer in use.
  • Properties: Used to manage configuration files (.properties). Only allows Strings for keys and values.

10.8 Collections Utility Class

The java.util.Collections class provides static methods for operating on collections.

  • sort(List l): Sorts elements in natural order.
  • binarySearch(List l, Object key): Efficient search in sorted list.
  • reverse(List l): Reverses the order of elements.
  • synchronizedList/Set/Map(): Returns thread-safe versions of collections.

10.9 Fail-Fast vs Fail-Safe Iterators

Feature Fail-Fast Fail-Safe
Concurrent Modification Throws ConcurrentModificationException Does NOT throw exception
Mechanism Works on original collection Works on a clone/copy of the collection
Memory Efficient High overhead due to copying
Examples ArrayList, HashSet, HashMap CopyOnWriteArrayList, ConcurrentHashMap
